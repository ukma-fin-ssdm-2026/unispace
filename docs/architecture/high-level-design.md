# Високорівневий дизайн системи
## 1. Архітектурний стиль
Проєкт UniSpace використовує гібридний архітектурний стиль: **Клієнт-серверна архітектура у поєднанні з багатошаровою моделлю бекенду**. 

- **Клієнт-сервер:** Забезпечує чіткий поділ між користувацьким інтерфейсом (Frontend) та бізнес-логікою (Backend), які спілкуються через REST API. Це дозволяє незалежно розробляти UI та серверну частину.
- **Багатошарова архітектура (Modular Monolith):** Бекенд фізично розгортається як єдине ціле (Django застосунок), але логічно розділений на ізольовані шари та сервісні модулі (маршрутизація/авторизація, бізнес-логіка, доступ до даних). Це знижує складність розробки для команди з 5 осіб у межах одного семестру, зберігаючи при цьому чистоту коду.

## 2. Огляд компонентів
Згідно з діаграмою компонентів системи, архітектура поділяється на наступні ключові блоки:

### Frontend (Client)
- **Client Application (Web UI):** Вебзастосунок, з яким взаємодіє кінцевий користувач (студент, викладач, адміністратор). Відповідає за відображення розкладу, пошук аудиторій та управління бронюваннями. Спілкується з бекендом через REST API (HTTPS).

### Backend (Business Logic)
Бекенд приймає HTTP-запити та керує бізнес-правилами системи.
- **API Gateway / Auth Service:** Точка входу для всіх запитів від клієнта. Відповідає за валідацію облікових даних, перевірку прав доступу та маршрутизацію запитів до відповідних внутрішніх сервісів.
- **Task Management Service:** Керує логікою бронювання та розкладом. Виконує перевірки на відсутність накладок.
- **Resource Management Service:** Керує довідником аудиторій, їхніми характеристиками (місткість, обладнання) та доступністю.
- **Reporting Service:** Відповідає за аналітику, генерацію звітів (зокрема звітів про конфлікти імпорту) та аудит-лог.
- **Data Access Layer (Entity Framework / ORM):** Надає уніфікований інтерфейс для роботи з базою даних, абстрагуючи бізнес-сервіси від прямих SQL-запитів.

### Data Layer
- **SQLite Database:** Основне сховище даних системи на етапі розробки. Зберігає інформацію про користувачів, розклад, аудиторії та аудит-лог. 

### External Services
- **Email Service (SMTP):** Зовнішній сервіс для асинхронної відправки сповіщень користувачам.
- **Calendar / CA3:** Існуюча система автоматизації закладу (САЗ), з якої UniSpace періодично імпортує базовий розклад (тільки для читання).

## 3. Огляд розгортання (Deployment)
Система розгортається на трьох базових вузлах:
1. **Пристрій клієнта (Client Node):** Веббраузер користувача, де виконується Frontend-застосунок.
2. **Сервер застосунку (Application Server):** Хостить Backend (Django-застосунки `Backend` та `Frontend`), надаючи REST API та вебсторінки.
3. **Сервер бази даних (Database Node):** Локальне сховище файлу `db.sqlite3` (у перспективі - окремий сервер PostgreSQL для продакшену).
