# Архітектурна матриця простежуваності (Architecture Traceability Matrix)

Цей документ відображає зв'язок між бізнес-вимогами (FR/US), нефункціональними вимогами (NFR) та логічними компонентами монолітної клієнт-серверної системи SpaceOps. Він гарантує, що кожна вимога має відповідний модуль для реалізації, а кожен компонент виконує конкретну бізнес-ціль.

## 2. Сценарії атрибутів якості (Quality Attribute Scenarios)

### Сценарій 1: Безпека (Security) - Захист від несанкціонованих дій
- **Джерело (Source):** Авторизований користувач із роллю "Студент".
- **Стимул (Stimulus):** Спроба надіслати HTTP-запит `POST /api/v1/bookings/change` на зміну існуючого бронювання.
- **Артефакт (Artifact):** `API Gateway` (шар авторизації моноліту).
- **Середовище (Environment):** Звичайна робота системи.
- **Реакція (Response):** `API Gateway` ідентифікує токен Microsoft, перевіряє прив'язану роль, блокує подальше виконання логіки в `Booking & Conflict Service` та логує спробу порушення доступу.
- **Міра реакції (Measure):** Запит відхиляється із статус-кодом `403 Forbidden` за час < 100 мс.

### Сценарій 2: Надійність (Reliability) - Відмовостійкість зовнішніх систем
- **Джерело (Source):** Внутрішній планувальник системи unispace.
- **Стимул (Stimulus):** Спроба ініціювати плановий імпорт розкладу, коли зовнішня система САЗ (CA3) недоступна.
- **Артефакт (Artifact):** `Booking & Conflict Service`.
- **Середовище (Environment):** Збій мережі або падіння зовнішнього API САЗ.
- **Реакція (Response):** Модуль фіксує таймаут з'єднання, перериває процес імпорту без пошкодження поточних даних у `PostgreSQL DB` та продовжує обслуговувати клієнтів.
- **Міра реакції (Measure):** 0% втрати існуючих даних; час відгуку системи для користувачів не деградує.

### Сценарій 3: Продуктивність (Performance) - Пікове навантаження на розклад
- **Джерело (Source):** Студенти (велика кількість одночасних користувачів).
- **Стимул (Stimulus):** 150 студентів одночасно відкривають сторінку свого розкладу на початку першої пари в понеділок.
- **Артефакт (Artifact):** `Client Web UI`, `API Gateway`, `Booking & Conflict Service`, `Django ORM / DAL`, `PostgreSQL DB`.
- **Середовище (Environment):** Режим пікового навантаження.
- **Реакція (Response):** Запити проходять через `API Gateway` до `Booking & Conflict Service`; спільний `Django ORM / DAL` виконує оптимізовані read-only запити до `PostgreSQL DB` з використанням MVCC (без блокування таблиць).
- **Міра реакції (Measure):** 95% запитів обробляються та повертаються клієнту за час ≤ 500 мс без помилок (HTTP 500/503).

### Примітка
Структуровано за допомогою ШІ. Верифіковано шляхом перевірки та аналізу Михайлик Ольгою (керівником простежуваності).
