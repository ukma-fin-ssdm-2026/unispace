# Матриця простежуваності вимог (RTM)

Цей документ візуалізує зв'язок між користувацькими історіями, системними вимогами та тестовими сценаріями системи бронювання UniSpace. Він створений для контролю якості та підтвердження того, що кожна заявлена вимога реалізована в коді й покрита відповідними перевірками.

## Легенда маркувань
- **US (User Story):** Користувацька історія.
- **FR:** Функціональна вимога (Functional Requirement).
- **NFR:** Нефункціональна вимога (Non-Functional Requirement). Категорії NFR:
  - **PERF:** Продуктивність (Performance).
  - **REL:** Надійність (Reliability).
  - **SEC:** Безпека (Security).
  - **USAB:** Зручність використання (Usability).
- **TC / PT / ST / UT:** Ідентифікатори тестів (Test Case, Performance Test, Security Test, Unit Test).
- **TBD / Планується:** Етап визначення або написання тесту.

#### Автоматизовані тести (Lab05–Lab06)

Стовпець «Автотести» містить назви тестів із `Backend/api/tests/test_views.py` (ендпоінти API) і `Backend/api/tests/test_audit_log.py` (бізнес-правило SEC-003). Тести запускаються через `pytest` локально та в CI на кожен pull request, з покриттям гілок і порогом `--cov-fail-under=75`.

Тести `test_views.py` перевіряють контракт API на реальній тестовій базі PostgreSQL: HTTP-коди (200/201/204/400/403/404), валідацію параметрів, єдиний формат помилок і контроль доступу. Бізнес-логіку, якої ще немає (накладки під час перенесення, підбір вільних аудиторій, конкурентні запити REL-001), вони не перевіряють, тому сценарії TC/PT/ST у стовпці «Тести» залишаються запланованими, а покриття позначено як часткове.

Тести також підтверджують атрибут якості **QA-04 (Validation)** з `docs/api/quality-attributes.md`: перевірені невалідні запити повертають контрольовану відповідь 400, а не 500. `OpenApiSchemaTests.test_schema_is_served` разом із перевіркою актуальності `openapi-generated.yaml` у CI підтримує **QA-05 (Maintainability)**.

`SyncLogSecurityTests` (3 тести: анонім і студент не бачать журнал синхронізації, диспетчер бачить) не мають окремого рядка в матриці: найближча вимога - загроза **TM-10** з `docs/architecture/threat-model.md` (запуск і перегляд синхронізації лише диспетчером).

Регресійні тести «анонім/студент не може видалити бронювання» з виправлення S-2, які загубилися під час переходу тестів на UUID, відновлено в `test_views.py`: захист `DELETE` (SEC-001, US-08) знову перевіряється автотестами.
