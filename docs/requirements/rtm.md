# Матриця простежуваності вимог (RTM)

Цей документ візуалізує зв'язок між користувацькими історіями, системними вимогами та тестовими сценаріями системи бронювання UniSpace. Він створений для контролю якості та підтвердження того, що кожна заявлена вимога реалізована в коді й покрита відповідними перевірками.

## Легенда маркувань
- **US (User Story):** Користувацька історія.
- **FR:** Функціональна вимога (Functional Requirement).
- **NFR:** Нефункціональна вимога (Non-Functional Requirement). Категорії NFR:
  - **PERF:** Продуктивність (Performance).
  - **REL:** Надійність (Reliability).
  - **SEC:** Безпека (Security).
  - **USAB:** Зручність використання (Usability).
- **TC / PT / ST / UT:** Ідентифікатори тестів (Test Case, Performance Test, Security Test, Unit Test).
- **TBD / Планується:** Етап визначення або написання тесту.

#### Автоматизовані тести API (Lab05)

Стовпець «Автотести» містить назви тестів із `Backend/api/tests.py`, які запускаються в CI (`python manage.py test -v 2`). Це тести контракту API для mock-ендпоінтів Lab04: вони перевіряють HTTP-коди (200/201/204/400/404), валідацію параметрів і єдиний формат помилок. Бізнес-логіку (накладки, ролі, зміну статусу) вони не перевіряють, бо її ще не реалізовано, тому сценарії TC/PT/ST у стовпці «Тести» залишаються запланованими, а покриття позначено як часткове.

Тести також підтверджують атрибут якості **QA-04 (Validation)** з `docs/api/quality-attributes.md`: усі перевірені невалідні запити повертають контрольовану відповідь 400, а не 500. `OpenApiSchemaTests.test_schema_is_served` разом із перевіркою актуальності `openapi-generated.yaml` у CI підтримує **QA-05 (Maintainability)**.

Ендпоінт `GET /api/v1/users/me/bookings/` (`UserBookingsTests`) не має прямої користувацької історії в цій матриці; найближча вимога — FR-007 (перегляд власних занять викладачем).
