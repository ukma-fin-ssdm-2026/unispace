# Журнал налагодження

Обрана помилка: **`suggest_rooms` пропонувала зайняті аудиторії, коли список зайнятих передавали генератором**
(модуль `Backend/api/room_suggestions.py`, TDD-функція підбору вільних аудиторій).

## Симптом

Виклик із зайнятими аудиторіями, заданими генератором, повертав і зайняті аудиторії. Тести при цьому були зелені.

```python
rooms = [make_room(i, capacity=30) for i in range(1, 5)]
busy_ids = (room.id for room in rooms[1:3])          # зайняті: аудиторії 2 і 3

suggest_rooms(rooms, min_capacity=10, busy_room_ids=busy_ids)
# очікувалось: [rooms[0], rooms[3]]
# фактично:    [rooms[0], rooms[1], rooms[2], rooms[3]]   <- зайняті 2 і 3 теж запропоновані
```

З множиною (`set`) або списком у `busy_room_ids` усе працювало правильно, тому помилка проявлялась лише
в окремих місцях виклику (наприклад, коли зайняті id збирали виразом-генератором із бронювань).

## Причина

Умова `room.id not in busy_room_ids` обчислювалась для **кожної** аудиторії окремо, а генератор можна пройти лише
один раз. Перша ж перевірка (`in`) «вичерпувала» генератор до кінця, і для всіх наступних аудиторій
`busy_room_ids` уже був порожнім, тож жодна з них не вважалась зайнятою. Перший тест на зайняті аудиторії використовував
`set`, тому цей випадок ніхто не перевіряв: тест перевіряв лише зручний для коду тип вхідних даних, а не контракт
«будь-який iterable».

## Виправлення

На початку `suggest_rooms` зайняті id один раз перетворюються на `frozenset`:

```python
busy_room_ids = frozenset(busy_room_ids)  # матеріалізуємо: генератор можна пройти лише один раз
```

Це також швидше (пошук у множині — O(1), а не O(n) для списку).

Регресійний тест у `Backend/api/tests/test_room_suggestions.py`:

- `test_busy_rooms_given_as_generator_are_all_excluded` — зайняті аудиторії 2 і 3 передано генератором, очікується
  `[rooms[0], rooms[3]]`.

## Урок

- Якщо функція приймає «будь-який iterable» (а в сигнатурі це не заборонено), тести мають перевіряти не лише `list`
  і `set`, а й одноразові ітератори та генератори.
- Вхідний iterable, який потрібно читати більше одного разу, одразу матеріалізувати (`frozenset(...)`/`list(...)`)
  на вході функції, а не покладатися на те, що викликач передасть повторно використовуваний об'єкт.
- Помилку одразу фіксувати тестом, що падає, і лише потім виправляти — тоді гарантовано, що тест справді ловить
  цю помилку.
