# План тестування (Test Plan)

**Обсяг (Scope):** 
У цьому плані тестується ключова бізнес-логіка бекенду UniSpace (REST API): механізм валідації тривалості бронювань, суворе дотримання контрактів помилок API та захист цілісності журналу аудиту (AuditLog). Ми свідомо **НЕ тестуємо** в цьому плані інтеграцію із зовнішніми системами (САЗ, Microsoft OAuth) та фронтенд.

**Критерії виходу (Exit criteria):**
Тестування вважається завершеним, коли:
1. 100% тестів з цього плану успішно проходять у CI (зелені).
2. Загальне покриття коду (`coverage`) становить не менше 75% (згідно зі стратегією тестування).
3. Немає жодного відкритого критичного дефекту (Severity: Blocker/Critical).

**Ризики (Risks):**
1. Найімовірніше зламається і найдорожче коштуватиме: механізм конкурентного бронювання (Race Conditions), коли кілька користувачів намагаються зайняти одну аудиторію одночасно. З нього починається перевірка.
2. Ризик цілісності даних: можливість обійти заборону на редагування `AuditLog` через масові операції (Bulk Update/Delete) в Django ORM.
3. Ризик надійності контрактів: зміна структури або кодів помилок API, що може зламати обробку помилок на клієнтському інтерфейсі.
